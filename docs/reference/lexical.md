# Lexical

Comments, identifiers, keywords, string forms, numbers, unit
literals, operators, sigils, directives, and attributes.

## Comments

`//` runs to the end of the line. Full-line and trailing forms both
work:

```weir
let retries = 3 // trailing
// full-line
print $"{retries}"
```

A `//` needs a space before it or must start the line. Inside a word
it is just text, so `http://a` in a command line stays one word.

On a command line, an unquoted `//` standing alone as an argument
starts a comment. Quote it (`"//"`) to pass the two characters to a
command.

`//` inside any kind of string is just text. Inside an interpolation
hole it is a parse error; write the comment outside the string:

```weir-error
print $"{1 // 2}" // a comment cannot live inside a hole
```

`///` lines are doc comments. A doc comment attaches to the
declaration directly below it. A blank line in between detaches it,
but an attribute line (`[<...>]`) in between does not. The text
shows on hover and in completion. On an `Args.load` field, the first
line is also the field's `--help` text.

## Identifiers

An identifier starts with a letter or `_` and continues with letters,
digits, `_`, or `'`.

Binding names start lowercase. Uppercase names are for types,
modules, and constructors:

```weir-error
let Foo = 1 // binding names start lowercase
print $"{Foo}"
```

## Keywords

A keyword can't be used as a name — `let let = 1` is refused with
`'let' is a keyword`.

<!-- keywords:begin — generated by tools/gen-lexical.weir; ci/e2e.sh gates the diff -->
| kind | keywords |
|---|---|
| shared with F# | `do`, `elif`, `else`, `false`, `for`, `fun`, `function`, `if`, `in`, `let`, `match`, `module`, `of`, `then`, `true`, `type`, `when`, `with` |
| weir's own | `always`, `from`, `import`, `plan`, `poll`, `pure`, `readonly`, `retry`, `to`, `until`, `within` |
| reserved, unused | `mutable`, `rec` |
| reserved for a helpful error | `def`, `return`, `try`, `while` |

After `within` comes the kind of scope: `cd`, `env`, `lock`, `proc`, `serve`, `tmp`.
Data is read with `from` (`json`, `jsonl`, `table`, `toml`, `xml`, `yaml`) and written with `to`
(`json`, `jsonl`, `yaml`). These words are special only in those positions;
anywhere else they are ordinary names.

`pure` and `readonly` each start their own indented block. Code in a
`pure` block may have no effects at all; code in a `readonly` block may
read (files, the environment, the clock, HTTP GETs) but change nothing.
`pure` also marks a function: `let pure f x = …`. Neither goes after `within`.
<!-- keywords:end -->

The reserved words are deliberate. Two of them, `rec` and `mutable`,
are reserved with no meaning, so writing them out of F# habit gives
an error instead of quietly binding a name:

```weir-error
let rec f x = x // 'rec' is reserved; weir has no let rec
print "y"
```

Four more are reserved only so that the error can help. weir has no
such constructs, but if you type one out of habit from another
language, the error tells you what to write instead: `while` points
at `retry`/`poll` and seq iteration, `return` at a function's last
expression, `try` at `| complete` and the `within` scopes, and `def`
at `let`:

```weir-error
while true do print "x" // 'while' is not a weir word — the error points at retry/poll
```

## Strings

Strings come in five literal forms, each written on one line. For text
that spans several lines, use a text block (below).

**Ordinary** — `"..."` with escapes `\"`, `\\`, `\n`, `\t`:

```weir
print "a\tb"
```

A line break inside an ordinary string is a parse error:

```weir-error
let s = "a
b" // strings close before end of line
print s
```

**Verbatim** — `@"..."`. Backslashes are literal, and `""` stands for
one quote character:

```weir
print @"C:\temp\x"
```

**Triple-quoted** — `"""..."""`. No escapes at all; a bare `"` is
fine inside. The string closes at the first `"""`.

**Interpolated** — `$"..."`. A `{expr}` is a hole; `{{` and `}}` are
literal braces:

```weir
let n = 2
print $"n={n} with {{literal braces}}"
```

**Raw interpolated** — `$"""..."""`. No escapes, but holes work, so
one string can contain a backslash, a bare quote and a hole.

There is no `$@"..."`:

```weir-error
print $@"x" // no verbatim-interpolated form; use $"""...""" instead
```

**Text blocks** — for text that spans several lines. A line ending in
`<<<` starts one: the indented lines below it are the text, and its
value is a `seq<string>` with one element per line.

- Everything inside is literal, including `$`, `{` and quotes.
- Indentation is kept relative to the first line. Blank lines inside
  the block are kept; blank lines at the end are dropped.
- `$<<<` puts values into the text with the same `{expr}` holes as
  `$"…"` strings; `{{` and `}}` are literal braces, and `$` stays as is.
- `$$<<<` uses `$name` and `${expr}` instead and leaves braces and
  quotes alone, which suits JSON or config templates. `$$` is a literal
  `$`, and a `$` that does not start a name stays as is, so `$1`
  survives. Values are inserted exactly as they are, so a value
  containing `"` or a newline can break the output; build the text with
  `to json` when values aren't trusted.
- The marker goes at the end of a line (`let x = <<<`) or alone on the
  line below. A marker with no indented block under it is an error.
- To pipe the whole block, put a `|>` line after it, at or left of the
  marker's column (`|> Seq.length`). A `|>` indented deeper than the
  text is just text.

```weir
let n = 2
let block = $<<<
    n={n} with {{literal braces}}
    $HOME stays a byte

block |> Seq.iter print
```

## Numbers

Integer literals are plain digits. A minus sign glued to the number or name after it, with a space (or
nothing, or another operator) before it, makes that value negative —
`-5`, `2 * -3`, and `f -1` passes −1 to `f`:

```weir
print $"{-5} {2 * -3}"
```

Spaced the same on both sides, it subtracts: `x-1` and `x - 1` both
mean x minus 1. (So `x -1` is not subtraction — it passes −1 to `x`.)

Float literals have a decimal point (`1.5`). Nothing converts
implicitly: mixing int and float is a type error that suggests
`Float.ofInt`:

```weir-error
print $"{3 / 2.0}" // no implicit widening; use Float.ofInt 3
```

A float is always finite. An operation whose result would be `NaN` or
`Infinity` raises an error:

```weir-error
print $"{1.0 / 0.0}" // float division by zero raises
```

Integer overflow raises rather than wrapping.

## Duration literals

Each literal has a single unit: `500ms`, `30s`, `2m`, `1h`.

```weir
print $"{90s + 45s}"
```

Compound literals do not exist — `1m30s` is a parse error:

```weir-error
let d = 1m30s // one unit per literal; write 90s, or add 1m + 30s
print $"{d}"
```

`show` renders the compound form (`90500ms` shows as `1m30.5s`), and
`Duration.parse` reads that form back.

## Size literals

Only binary units have literals: `10MiB`, `4KiB`, `1GiB`.

```weir
print $"{1KiB + 512B}"
```

The SI suffixes are not literals:

```weir-error
let s = 10MB // binary units only in literals; Size.parse reads SI text
print $"{s}"
```

`Size.parse` accepts SI suffixes in text it reads, as powers of ten.

## Operators

Every infix operator, from lowest precedence to highest. All are
left-associative:

| binds | operators | meaning |
|---|---|---|
| loosest | `\|>` `>>` | pipe-apply; function composition (left to right; no `<<`/`<\|`) |
| | `\|\|` | boolean or |
| | `&&` | boolean and |
| | `==` `<>` `<` `<=` `>` `>=` | equality and comparison |
| | `+` `-` | additive |
| tightest | `*` `/` `%` | multiplicative; `%` is integer remainder |

A minus sign directly before a value negates it, even after another
operator (`2 * -3`).

`%` is integer remainder. How it handles signs (truncated, unlike
Python's floored `%`) and why floats are refused are covered in
[Types](types.md#scalars).

The one precedence rule that tends to surprise: `|>` and `>>` share
the loosest level, so `xs |> f >> g` is `(xs |> f) >> g`. The error
message says so:

```weir-error
[1; 2] |> Seq.map show >> Seq.length // '>>' and '|>' share precedence; write xs |> (f >> g)
```

`=` is not equality. It binds a value in `let` and record fields, and
using it as a comparison is a check error that suggests `==`:

```weir-error
if 1 = 1 then print "eq" // use '==' for equality
```

**`|` is not in the table** because it is the command pipe, not an
operator. Which one you use depends on the right-hand side:
`git log | grep x` feeds a program, `git log |> Seq.head` applies a
function, and using the wrong one is an error that names the right
one.

## Sigils

These are all of weir's sigils:

| sigil | where | meaning |
|---|---|---|
| `$name` | command argv | splice a binding as exactly one argv word |
| `$@xs` | command argv | splat a seq: N elements become N words |
| `$(...)` | expression | capture a command chain's output |
| `$e(...)` | expression | the same, under the env overlay bound to `e` |
| `^cmd` / `^$name` | command name | always run an external program: one named literally, or by a `$`-spliced value |
| `_.field` | expression | field-access shorthand (`fun x -> x.field`) |
| `_[i]` | expression | index shorthand (`fun x -> x[i]`) |
| `_` | patterns | the wildcard |

weir has no `!` for negation; use the word `not`:

```weir-error
if !true then print "x" // '!' is not negation — write 'not true'
```

## Directives

A `#` line is an instruction to the tooling, not part of the
language. Some directives are read when a script is checked; others
run immediately, either from the REPL's init file (read once at
startup) or typed at the REPL prompt. Each directive belongs to
exactly one of these three contexts:

| directive | purpose | context |
|---|---|---|
| `#sig` | bind a command signature file | script file, read at check time |
| `#schema` | the schema a `yaml` block is checked against (currently written as `schema=` on the marker line) | script file, read at check time |
| `#session` | session settings: cwd, env, echo cap, log level | init.weir, read once at startup |
| `#alias` | a command alias (`#alias k = kubectl`) | init.weir (also works at the prompt) |
| `#help` | the directives, the modules, one member's doc | REPL prompt, runs now |
| `#find` | fuzzy help search (fzf + live preview; substring fallback) | REPL prompt, runs now |
| `#echo` | how many elements of a lazy seq the REPL echoes | REPL prompt, runs now |
| `#infer` | draft named types from a JSON/YAML sample | REPL prompt, runs now |
| `#save` | distill the session to a runnable script | REPL prompt, runs now |
| `#history` | show history (`#history` all, `#history N` last N); prints the file path | REPL prompt, runs now |
| `#quit` | leave the REPL | REPL prompt, runs now |

The [REPL manual](../repl.md) covers the prompt set and the init
file. [Signatures](../tooling.md#command-signatures) and
[schemas](../tooling.md#yaml-schemas) cover the check-time ones.

## Attributes

`[<...>]` attributes are read at check time and have no effect at
runtime. The set is fixed.

For command-line flags (`Args.load`):

- `[<Short "c">]` — pin a one-character short flag (`"h"` is
  reserved for `--help`)
- `[<NoShort>]` — suppress the derived short
- `[<Default lit>]` — a literal default: string, int, float, bool,
  duration, or size

For data read and written with the adapters ([Adapters](adapters.md)):

- `[<Wire "key">]` — the JSON/YAML key for a field, when that key is
  not a legal weir identifier
- how a time, duration or size is encoded: `[<Iso8601>]`,
  `[<EpochMs>]` or `[<EpochSec>]` on an `Instant`; `[<Millis>]` or
  `[<Seconds>]` on a `Duration`; `[<ByteCount>]` on a `Size`
- `[<Tag "field">]` on a union, naming the field that says which case
  it is, and `[<Other>]` on the case that takes any unknown value
- `[<Attr>]` and `[<Elem "Name">]` for XML attributes and repeated
  child elements

And `[<Positional>]`, in signature files only, where a foreign CLI's
operands need describing.

A typo is a check error with a did-you-mean:

```weir-error
type Cli = {
    [<Shrot "c">]
    clean: bool
}
let c = Args.load Cli // unknown attribute 'Shrot'. Did you mean 'Short'?
print $"{c.clean}"
```

## The other literals

`true` and `false` are keywords. `()` is the unit literal, the value
an effect returns.

There is no `char` type; a single character is just a one-character
string:

```weir-error
let c = 'a' // no char type; "a" is a one-character string
```

`Duration` and `Size` have literals; `Instant` deliberately does not.
You get a point in time from `Instant.now ()`, `Instant.parse` or
`Instant.parseWith`.

## Statement layout

A statement starts at column 0; the full layout and block rules are
[Statements](statements.md#layout).

## In command argv

None of the above applies inside a command's argv. `30s`, `10MiB`, a
glued `//`, and a `{brace}` are all ordinary words there; it is up to
the program to interpret its arguments.
